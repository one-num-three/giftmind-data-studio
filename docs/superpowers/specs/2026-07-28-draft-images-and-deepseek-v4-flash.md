# GiftMind 草稿图片与 DeepSeek V4 Flash 规格

## 背景与目标

GiftMind 当前只在礼物已经保存、取得 `gift_id` 后显示图片管理器，导致采集同学在新建礼物时看不到图片入口。同时，DeepSeek 接口、状态页和测试仍使用旧模型名 `deepseek-chat`。

本次目标：

1. 新建礼物时立即显示图片选择入口。
2. 图片在礼物首次保存前只保存在当前页面的待上传队列中。
3. 礼物保存成功后，使用返回的 `gift_id` 自动上传全部待处理图片。
4. “保存并新建下一条”必须等图片上传成功后再清空表单。
5. DeepSeek 模型统一为 `deepseek-v4-flash`。

## 用户流程

### 新建礼物

1. 采集同学可选择一张或多张 JPEG、PNG、WebP 图片。
2. 页面立即显示本地缩略图、文件名、大小和删除按钮。
3. 页面在选择时检查格式和 8MB 单张限制；不合格文件不会进入队列，并显示明确原因。
4. 点击任一保存按钮后，系统先创建礼物，再上传待处理图片。
5. 全部图片上传成功后显示成功状态。
6. “保存并新建下一条”只有在礼物和图片全部成功后才清空当前表单和图片队列。

### 上传失败

1. 已成功创建的礼物保留在数据库中。
2. 上传失败的图片继续留在待处理队列。
3. 页面显示失败图片及原因，并提供“重试上传”。
4. 表单不会被重置；用户可继续编辑、删除失败图片或重试。
5. 已上传成功的图片不重复上传。

### 编辑已有礼物

已有图片照常从服务器加载。新选择的图片可以立即上传；失败时进入待处理队列并允许重试。服务端图片可单独删除。

## 技术设计

`ImageManager.vue` 接收可选的 `giftId`：

- 无 `giftId`：维护内存中的 `PendingImage[]`，使用 Object URL 预览。
- 有 `giftId`：加载服务端图片；选择新图片时调用现有上传接口。
- 对父组件暴露 `uploadPending(giftId): Promise<void>`、`hasPending(): boolean` 和 `clearPending(): void`。
- 每个待上传项有稳定客户端 ID、文件、预览 URL、状态和错误信息。
- 组件移除图片或卸载时撤销 Object URL。

`GiftWorkbenchView.vue` 负责保存编排：

1. 运行现有表单校验和重复检测。
2. 调用 `store.saveDraft()`，取得保存后的 `GiftRead`。
3. 调用 `imageManager.uploadPending(saved.id)`。
4. 仅在上述两步都成功后执行清理；若是下一条，再调用 `store.startNew()`。

Store 保留底层保存职责，不再由页面调用会提前清空的 `saveAndCreateNext()`。

后端定义单一常量：

```python
DEEPSEEK_MODEL = "deepseek-v4-flash"
```

状态查询、保存密钥后的响应和 DeepSeek 请求全部引用该常量。`.env` 仍只保存 `DEEPSEEK_API_KEY`，不在网页回显密钥。

## 数据与安全边界

- 本次不新增账户、角色、CSRF、限流或临时上传表。
- 保存前图片不上传服务器，因此不会产生没有礼物归属的孤立图片。
- 图片不写入 localStorage；刷新页面后待上传图片会丢失，界面应提示“图片需在本次页面保存”。这是初级采集工具阶段可接受的权衡。
- 服务端继续限制 JPEG、PNG、WebP 和单张 8MB。

## 与 AI 选品助手的关系

后续右侧 AI 助手采用独立的 `draft_id/thread_id`，聊天附件与礼物图片分开管理：

- 礼物图片是最终数据库资产。
- 聊天附件是 AI 的输入来源，经过人工审核后可以选择加入礼物图片。
- AI 只返回字段建议补丁，不直接保存礼物。
- 文本和链接优先实现；图片 OCR/视觉描述在单独阶段实现。

这种边界允许后续增加活动、商品或新礼物类型及字段，而不改变本次图片上传协议。

## 验收标准

- 新建礼物页面无需先保存即可看到图片入口。
- 可一次选择多图并预览、移除。
- 非支持格式或超过 8MB 会被前端拒绝。
- 首次保存请求先创建礼物，随后上传图片到返回的礼物 ID。
- 上传失败时表单和失败图片保留。
- 保存并新建时，成功上传后才清空。
- `/api/settings/deepseek` 返回 `deepseek-v4-flash`。
- `/api/ai/suggest` 请求使用 `deepseek-v4-flash`。
- 前后端测试、类型检查和生产构建通过。
